# v0.3 profile repeat audit and measurement plan

This audit follows the published v0.2 post-hoc analysis. It changes no
frozen v0.2 inputs or conclusions. The source profiles are RTX 4070 and
GB10 at revision `0.21.0-posthoc` in commit `d26fa24`. The proposed
measurements are microbenchmarks and require review before collection.

## What the profiles establish

A timed sample is one observation within a sweep. An independent repeat
is a fresh process running the sweep. The profile stores rounded
median and bootstrap interval values. It has no sample count, repeat
count, or point-level raw receipt. Equal interval endpoints can occur
with repeated identical or rounded readings and with derived and
clipped metrics. They cannot identify single timed samples. No curve
field can be verified as having exactly one timed sample from the
published evidence. The inventory below marks curves backed by a
single contributing sweep separately from fields where repeat
provenance is unavailable.

For RTX 4070 the two contiguous curves match those in `a4fc6e3`. The
collector requests 11 timed samples per point for `mlp` and 7 for
`strided-mlp`, each invoked once in a full calibration. No
independent-repeat aggregate is documented for the shipped RTX 4070

nonzero interval widths in the shipped profile. Their shipped values

samples or per-run clock and thermal records.

## Proposed collection

1. Use the same pinned microbenchmark sources on Bifrost RTX 4070 and
   Spark 1 GB10. Build for `sm_89` and `sm_121` respectively. Verify
   exact geometry keys and units against the shipped MLP matrices.
2. Run five fresh processes per benchmark per GPU, with 15 timed
   samples per point. Use `mlp --samples 15 --warmup 3` for contiguous
   DRAM and L2 and `strided-mlp --samples 15 --warmup 3` for strided
   DRAM. Keep each benchmark's existing working sets, issue modes,
   read-only DRAM eviction and warm L2 preparation. Repeat the whole
   registered grid, including the outliers and their neighbors.
3. Hold `flock /tmp/virtualgpu-gpu.lock` for each invocation. Check
   compute processes and display activity before and after. Defer
   the 4070 when gaming or other GPU work is active. On Spark 1 also
   check CPU and memory activity because the GPU shares host memory.
   Warm the devices to a stable temperature, use verified locked
   clocks when available, and otherwise record frequencies, temperature,
   throttling and power policy. Preserve and report any protocol
   failure separately. Keep completed independent repeats in UTC
   order and retain all valid samples.
4. Join by full geometry keys, require five complete repeat rows per
   key, and use the median of the five within-sweep medians. Publish
   all five medians and their minimum and maximum. Archive the pooled
   75-sample median and interquartile range per point as descriptive
   statistics across individual timed observations. Use the existing bootstrap median interval
   over the five independent sweeps as a coarse interval. Apply the
   existing clock uncertainty calculation with measured drift and the GB10
   record-only uncertainty floor. Preserve observed nonmonotonicity.
   Audit the read bandwidth scalars that can alias an MLP peak. If a
   scalar used an old point, recompute it from its independent
   bandwidth sweep and the refreshed MLP peak using the existing
   maximum rule, with its input sources recorded.
5. Increment both profile revisions from the latest merged revisions
   (proposed `0.22.0-posthoc` if available). Publish a calibration
   manifest digest referencing the previous profile, source and
   binary SHA, GPU identity, driver, toolkit, commands, run IDs,
   UTC, host checks, raw samples and telemetry SHA-256, and the
   reduction procedure. Validate schema and profile consumers and
   review the field-level diff before freezing. Keep this calibration
   separate from workload labels and evaluation commits.
